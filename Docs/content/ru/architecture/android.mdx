# Android {/* #android */}

Hyprism на Android состоит из двух приложений. Лаунчер это обычный интерфейс Hyprism, собранный для Android, а хост игры запускает клиент Hytale для macOS arm64 нативно на процессоре устройства через загрузчик Mach-O. Эмулятор процессора не используется: инструкции arm64 клиента выполняются напрямую, а переводятся только интерфейсы операционной системы.

![Главное меню Hytale с кнопками Worlds, Mods, Minigames, Servers и My Avatar и аватаром игрока на Galaxy S23](/img/android/main-menu.png)

На этой странице описана поддерживаемая архитектура. Шаги сборки приведены в [руководстве по разработке для Android](/development/android).

## Компоненты {/* #components */}

| Компонент | Исходники | Назначение |
| --- | --- | --- |
| APK лаунчера | [`Sources/Hyprism.Android`](../../../../Sources/Hyprism.Android) | Голова Avalonia, которая компилирует общий интерфейс из `Hyprism.Desktop`, выполняет вход и передаёт запуск хосту игры |
| APK хоста игры | [`Sources/Hyprism.MachOLoader/android`](../../../../Sources/Hyprism.MachOLoader/android) | Наследник `SDLActivity`, который загружает `libmain.so` и запускает клиент |
| Загрузчик Mach-O | [`Sources/Hyprism.MachOLoader/src`](../../../../Sources/Hyprism.MachOLoader/src) | Отображает клиент и его библиотеки dylib в память, применяет fixups и связывает импорты с прослойками |
| Библиотеки хоста | Собираются `deps.sh` | SDL 3.2.26, MobileGlues (настольный OpenGL поверх OpenGL ES) и OpenAL Soft 1.24.3 |

Лаунчер сохраняет имя сборки `Hyprism.Desktop`, поэтому ресурсы `avares://Hyprism.Desktop/` и имена `Hyprism.Desktop.Localization.Resources` разрешаются без изменений. Содержимое окна находится в `MainView`: на десктопе его показывает `MainWindow`, а на Android его напрямую показывает активность.

## Процесс запуска {/* #launch-flow */}

1. Лаунчер выполняет вход для выбранного официального профиля теми же службами Core, что и на десктопе.
2. `GameLauncher` находит зарегистрированный `IExternalGameHost` и вместо запуска процесса передаёт `--name`, `--uuid`, `--auth-mode`, `--identity-token` и `--session-token` в `AndroidGameHost`.
3. `AndroidGameHost` запускает `org.hyprism.game/.HytaleActivity`, передавая аргументы в дополнительном поле намерения `org.hyprism.game.ARGUMENTS`.
4. SDL вызывает `SDL_main` из `libmain.so` в своём потоке `SDLThread` со стеком 64 МиБ. Хост добавляет `--app-dir` и `--user-dir`, читает необязательные `env.txt` и `args.txt` и вызывает загрузчик.
5. Загрузчик отображает `HytaleClient`, запускает его инициализаторы и вызывает его `main`.

Игра должна работать в `SDLThread`, потому что SDL 3 перенаправляет вызовы окна из других потоков в этот поток и ждёт его.

Файлы игры находятся во внешнем каталоге файлов хоста и повторяют структуру пакета macOS:

```text
<files>/Client/Hytale.app/Contents/MacOS/HytaleClient
<files>/Client/Hytale.app/Contents/MacOS/Data/
<files>/Assets.zip
<files>/UserData/
<files>/MG/                 настройки, кэш и журнал MobileGlues
<files>/env.txt             необязательные строки NAME=value
<files>/args.txt            необязательные дополнительные аргументы клиента
```

## Загрузчик Mach-O {/* #mach-o-loader */}

Загрузчик обрабатывает исполняемый файл и каждую поставляемую dylib, которую клиент открывает через `dlopen`.

| Возможность | Подробности |
| --- | --- |
| Контейнеры | Тонкие Mach-O arm64 и универсальные бинарные файлы (срез arm64) |
| Память | Сегменты копируются в анонимную память, потому что Android запрещает исполняемые отображения файлов данных приложения |
| Fixups | `LC_DYLD_CHAINED_FIXUPS` (форматы указателей 2 и 6) и классические опкоды rebase и bind из `LC_DYLD_INFO_ONLY` |
| Символы | Деревья экспорта, зависимости `@rpath` рядом с загружающим образом и плоский поиск |
| Локальные переменные потока | Один блок на образ и поток за переходником `tlv_get_addr`, который сохраняет все регистры, кроме `x0`, `x16` и `x17` |
| Старт | Инициализаторы `__init_offsets` и `__mod_init_func`, затем `LC_MAIN` |
| Отсутствующие импорты | Заглушка, которая записывает имя символа; с `MACHO_SOFT_TRAPS=1` она возвращает 0 вместо завершения |

Импорты из системных библиотек Darwin связываются с прослойками. Импорты между поставляемыми dylib связываются с их экспортами. `dlopen` системной библиотеки возвращает виртуальный дескриптор, `dlsym` которого ищет в прослойках.

## Слои прослоек {/* #shim-layers */}

Прослойки сохраняют соглашение о вызовах и раскладку данных Darwin с одной стороны и вызывают Bionic с другой.

| Файл | Что покрывает |
| --- | --- |
| `shims.c` | Функции libc с совпадающим ABI, errno, объекты pthread со статическими инициализаторами Darwin, службы dyld, таблицы ctype, время Mach |
| `posix.c` | Файлы, раскладки `stat` и `dirent`, флаги `open` и `fcntl`, вариативный stdio, `mmap`, Mach VM, `sysctl`, `sysconf`, пользователи, `clonefile` и `fcopyfile` |
| `signals.c` | Номера и флаги сигналов и обработчик хоста, который преобразует `ucontext` Linux и Darwin и записывает нативные сбои |
| `net.c` | Раскладки `sockaddr`, параметры сокетов, `msghdr`, `getaddrinfo`, интерфейсы и `kqueue` поверх `epoll` |
| `crypto.c` | Дайджесты CommonCrypto, HMAC, PBKDF2, AES и случайные байты |
| `cf.c`, `objc.c` | Небольшие CoreFoundation и среда выполнения Objective-C с классами Foundation, которым клиент отправляет сообщения |
| `cxx.c` | Функции libc++, которые импортируют поставляемые dylib, на альтернативной раскладке `std::string` от Apple |
| `dyld.c` | `dlopen` и `dlsym`, замены библиотек и загрузка поставляемых dylib |
| `gl.c` | Точки входа OpenGL с раскладкой аргументов в стеке Darwin, началом координат `gl_FragCoord` в левом верхнем углу и необязательной трассировкой загрузок |
| `security.c` | SecureTransport, `SecTrust` и `SecCertificate` поверх TLS и хранилища доверенных сертификатов платформы, а также `SecKey`, `SecItem` и связки ключей в памяти поверх криптопровайдера платформы |
| `sdl_scale.c` | Направляет `SDL_GL_GetProcAddress` через `gl.c` и при необходимости сообщает координаты окна и мыши в точках |

Главные правила совместимости, которые реализуют прослойки:

- Вариативные функции Darwin передают все вариативные аргументы через стек. `printf`, `open`, `fcntl` и похожие функции входят через ассемблерный код, который передаёт указатель стека вызывающего кода в C.
- Darwin упаковывает аргументы в стеке по их естественному размеру, а AAPCS64 отводит каждому слот 8 байт. Функция с более чем восемью целочисленными аргументами и двумя или более 4-байтовыми значениями в стеке входит через переходник `STACK_ARGS`, который передаёт в C область стека вызывающего кода. Это касается `glTexSubImage3D`, `glCompressedTexSubImage3D`, `glBlitFramebuffer`, `glCopyImageSubData` и `CCCryptorCreateWithMode`; без этого атлас интерфейса клиента загружался с неверным типом пикселей и оставался пустым.
- В Linux и Darwin значения errno от 1 до 34 совпадают, кроме 11: в Linux это `EAGAIN`, а в Darwin `EDEADLK`. Неверный перевод превращает каждое неблокирующее чтение сокета без данных в неизвестную ошибку сокета.
- `setjmp` и `longjmp` хранят собственную раскладку регистров внутри 192-байтового `jmp_buf` Darwin, который меньше, чем в Bionic.
- `___chkstk_darwin` получает размер выделения в `x9`, в байтах.
- Ячейка errno хранит нумерацию Darwin. При каждом обращении к `__error()` errno хоста сбрасывается в сторожевое значение, поэтому ошибка после того, как программа обнулила errno, не теряется.
- `isalpha` и родственные функции в Darwin встраиваемые и читают `_DefaultRuneLocale.__runetype` по смещению `0x3c` с битами `_CTYPE_*` Darwin.
- Пулу переходников NativeAOT нужны результаты `vm_allocate` и `vm_remap`, выровненные на 16 КиБ, с копией кода для чтения и выполнения и половиной данных для чтения и записи.
- Состояния `CC_*_CTX` и `CCHmacContext` помещаются в структуры вызывающего кода без указателей, потому что вызывающий код их копирует.

## Замены библиотек {/* #library-replacements */}

| Поставляемая библиотека macOS | На Android |
| --- | --- |
| `libSDL3.dylib` | `libSDL3.so` (SDL 3.2.26) |
| `libopenal.dylib` | `libopenal.so` (OpenAL Soft 1.24.3, OpenSL ES) |
| `libicucore` | Недоступна; загрузчик включает инвариантную глобализацию .NET |
| `OpenGL.framework` | MobileGlues, который также предоставляет слой EGL для SDL |
| `libsodium.dylib`, `libwuffs.dylib`, `Noesis.dylib` и другие простые dylib на C | Загружаются загрузчиком как Mach-O |

Поставляемая dylib, которая связана с заменённой библиотекой, связывается с той же библиотекой Android. `libSDL3_image.dylib` связана с `libSDL3.dylib`, и загрузка SDL для macOS второй копией приводила к ошибке `That operation is not supported` при сохранении изображений.

Хост задаёт `SDL_OPENGL_LIBRARY` и `SDL_EGL_LIBRARY` равными `libmobileglues.so` и записывает `MG/config.json` с `customGLVersion` 41, потому что клиенту нужен контекст OpenGL 4.1 core.

## Графика {/* #graphics */}

Клиент рисует через OpenGL 4.1 core с помощью MobileGlues, который переводит GLSL в OpenGL ES. `gl.c` адаптирует вызовы там, где они различаются:

| Различие | Обработка |
| --- | --- |
| Функции с более чем восемью целочисленными аргументами читают упакованные аргументы в стеке Darwin | Переходники `STACK_ARGS` для `glTexSubImage3D`, `glCompressedTexSubImage3D`, `glBlitFramebuffer` и `glCopyImageSubData` |
| В OpenGL ES нет `layout(origin_upper_left)` для `gl_FragCoord` | Фрагментный шейдер с этим объявлением получает макрос, который отражает y относительно высоты области просмотра; высота хранится в uniform и обновляется через `glViewport` и `glUseProgram` |
| В GLSL ES нет инициализаторов uniform, поэтому `uniform float uOpacity = 1.0;` читается как 0 | Константные значения разбираются из исходника и задаются через `glUniform*` после каждого `glLinkProgram` |

Шейдер пакетной отрисовки интерфейса проверяет маски текста и области отсечения в координатах окна от левого верхнего угла. Без отражения эти проверки проходили только элементы около вертикального центра экрана. Без инициализаторов предпросмотр аватара рисовался с общей прозрачностью 0.

## TLS и сертификаты {/* #tls-and-certificates */}

`SslStream` клиента использует SecureTransport и сам проверяет каждую цепочку сервера после рукопожатия, как в macOS. `security.c` реализует эти API поверх `org.hyprism.game.TlsBridge` в APK хоста через JNI:

1. `SSLHandshake`, `SSLRead` и `SSLWrite` передают байты между обратными вызовами ввода-вывода клиента и `SSLEngine`. Движок принимает любой сертификат, потому что клиент отклоняет недоверенные цепочки на следующем шаге.
2. `SSLCopyPeerTrust` возвращает сертификаты сервера. Затем клиент вызывает `SecTrustCreateWithCertificates` и `SecTrustEvaluateWithError`.
3. `TlsBridge.verify` строит и проверяет цепочку с помощью `X509TrustManagerExtensions` и хранилища доверенных сертификатов Android или с собственными якорями, заданными через `SecTrustSetAnchorCertificates`.
4. `SecTrustCopyResult` сообщает об ошибке как `AnchorTrusted` у корня или `TemporalValidity` у конечного сертификата, и .NET переводит это в свои флаги состояния цепочки.

Ключи для сертификата сеанса клиента проходят через `org.hyprism.game.KeyBridge`. Ключ хранит внешнее представление Apple (`04||X||Y||K` для EC, PKCS#1 для RSA). `SecItemExport` записывает закрытые ключи как `EncryptedPrivateKeyInfo` PBES2 (PBKDF2-HMAC-SHA256 и AES-256-CBC), потому что .NET расшифровывает этот экспорт и через него же переносит ключ во временную связку ключей. PBKDF2 вычисляется прямо через SHA-256, потому что провайдер платформы отклоняет пустой пароль, который использует .NET.

`TlsBridge` и `KeyBridge` разрешаются в `SDLThread` до запуска клиента, потому что сетевые потоки клиента не видят классы приложения. TLS на стороне сервера и клиентские сертификаты не поддерживаются.

## Текущие ограничения {/* #current-limits */}

- Локальные миры не запускаются, потому что клиент запускает сервер мира отдельным процессом.
- Сертификат сеанса пока не создаётся: клиент не может расшифровать экспорт закрытого ключа, поэтому серверы отклоняют подключение с `Client certificate required for mTLS connection`.
- Перечисление шрифтов CoreText не реализовано.
- Строка состояния Android закрывает верх игры.
- Лаунчер остаётся в состоянии запуска после передачи игры.
- Касания доходят до клиента только как события мыши SDL.
